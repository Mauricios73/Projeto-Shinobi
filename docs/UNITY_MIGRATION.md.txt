Projeto Shinobi — Plano de Migração GameMaker → Unity
1. Objetivo

Migrar o Projeto Shinobi atualmente desenvolvido em GameMaker para Unity, utilizando C#.

A migração não será uma conversão automática de GML para C#.

O projeto GameMaker será utilizado como:

referência de gameplay;
referência de comportamento;
referência visual;
referência de estados;
referência de combate;
referência de IA;
referência de habilidades;
referência de clima e ambiente;
referência de áudio;
referência de interface.

A implementação final será reconstruída seguindo uma arquitetura modular própria para Unity.

Regra principal

Preservar o comportamento do jogo, não o código do GameMaker.

2. Estado atual

O projeto original está em:

Ultimo Uchiha - versão 3

Repositório:

Mauricios73/Projeto-Shinobi

Branch principal:

main

O GameMaker continuará preservado durante toda a migração.

Não fazer
apagar o projeto GameMaker;
substituir o projeto GameMaker pela Unity;
converter GML automaticamente;
copiar arquitetura problemática simplesmente porque já funciona;
reescrever tudo sem testar;
migrar vários sistemas simultaneamente.
Fazer

Criar uma nova implementação Unity baseada no comportamento existente.

6. Fase 0 — Backup

Antes de iniciar a Unity:

git status

O projeto GameMaker precisa estar salvo.

Depois:

git add .
git commit -m "chore: save GameMaker state before Unity migration"
git push origin main

Opcionalmente criar uma tag:

git tag -a gamemaker-pre-unity -m "Stable GameMaker version before Unity migration"
git push origin gamemaker-pre-unity

Essa tag representa o ponto:

Última versão estável do GameMaker antes da migração.

21. Dificuldade

A dificuldade não deve criar três IAs completamente diferentes.

Em vez disso:

Enemy AI
   │
   ├── Easy
   ├── Medium
   └── Hard

alterará parâmetros como:

ReactionTime
AttackProbability
DefenseProbability
DodgeProbability
Aggression
DetectionRange
DecisionInterval
Accuracy

Assim:

Easy
→ menos agressivo

Medium
→ comportamento equilibrado

Hard
→ mais rápido/agressivo

Ainda deve ser possível acertar o inimigo.

32. O que NÃO será migrado diretamente

Não copiar diretamente:

GML → C#

Também não copiar:

obj_xxx → MonoBehaviour

automaticamente.

Um objeto GameMaker que contém 2.000 linhas não precisa virar um script Unity de 2.000 linhas.

A lógica deve ser dividida.

Exemplo:

GameMaker

obj_player
    ↓
Unity

PlayerController
PlayerMovement
PlayerStateMachine
PlayerCombat
PlayerAbilities
PlayerAnimator
PlayerStats
